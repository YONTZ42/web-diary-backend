# LambdaContainers

## 概要

`LambdaContainers` は、画像処理を Django API 本体から分離するための Lambda コンテナ群です。  
重い推論処理を App Runner の常駐 API に抱え込ませず、処理特性ごとにスケール単位を分けることを目的にしています。

この分離により、通常の API リクエストと画像処理バーストを別々に最適化できます。  
その代わり、イメージ管理やコールドスタートといったサーバレス特有のトレードオフは受け入れています。

## ディレクトリ構成

- `Lambda_CropYOLO/`
  YOLO セグメンテーションで被写体を抽出し、RGBA PNG として切り抜く Lambda
- `Lambda_CropYOLO_Multi/`
  複数マスクを検出し、S3 に保存したマスク画像 URL を返す Lambda
- `Lambda_RembgIsnet/`
  `isnet-general-use` を使った背景除去 Lambda
- `Lambda_RembgIsnetAnime/`
  アニメ寄り画像を想定した背景除去 Lambda
- `Lambda_RembgBirefnet/`
  `birefnet-general-lite` を使った背景除去 Lambda
- `Lambda_Genai/`
  生成 AI 系の実験・拡張用コンテナ

## YOLO に関する説明

YOLO 系 Lambda では `ultralytics` を使い、セグメンテーションモデルで対象物の輪郭マスクを抽出しています。

- `Lambda_CropYOLO`
  推論結果の中から最も有力なマスクを選び、元画像に alpha を付与して切り抜き PNG を生成
- `Lambda_CropYOLO_Multi`
  検出された複数マスクを個別 PNG として S3 に保存し、URL を返却

この設計の狙いは、単なる背景除去よりも「被写体単位の切り抜き」を安定して扱うことです。  
MiniatureMuseum のように展示物として見せる用途では、雑な矩形 crop よりセグメンテーション結果の方が UI 品質に直結します。

## rembg に関する説明

rembg 系 Lambda は、背景除去モデルをコンテナに同梱した上で Lambda 上で実行します。  
`/tmp` を使ったモデル配置や Numba 周辺設定を行い、Zip 配布では扱いづらい依存関係をコンテナで吸収しています。

モデルを複数用意している理由は、入力画像の特性に応じて品質と速度のバランスを選べるようにするためです。

- IS-Net
  汎用的で扱いやすい
- BiRefNet
  より高品質寄りの選択肢
- Anime 向けモデル
  イラスト系入力への最適化

## なぜ Lambda コンテナか

- 画像処理ライブラリや推論モデルを含む実行環境をそのままパッケージ化しやすい
- API 本体と別にスケールし、スパイク時の影響範囲を切り分けやすい
- App Runner 側を軽く保ち、通常 API の応答性を守りやすい

## スケーラビリティとトレードオフ

- メリット
  画像処理を App Runner から分離でき、処理ごとに独立してスケールしやすい
- メリット
  モデルやネイティブ依存を含む大きなランタイムでもコンテナで扱いやすい
- トレードオフ
  コールドスタートや大きいイメージの pull コストがある
- トレードオフ
  推論モデルの更新時は ECR イメージ管理と互換性確認が必要

## 開発速度の観点

画像処理をすべて Django 内へ閉じ込めるより、Lambda ごとに責務を切った方が変更影響を限定しやすくなります。  
一方でサービス数は増えるため、README や IaC、監視をセットで整備しないと保守負荷は上がります。  
このリポジトリでは `aws-infra/` と合わせてその運用コストを吸収する設計にしています。
